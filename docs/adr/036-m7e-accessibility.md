# ADR-036: Accessibility matrix: every state of every tool, checked four ways, and the fixes it found

**Status:** Implemented under the approved M7 gate; owner acceptance pending
**Date:** 2026-10-23
**Scope:** A standing browser test that takes every page and every state of every tool and checks it the way four kinds of visitor meet it (automated rules, keyboard only, screen reader, enlarged text on a narrow screen); and the fixes that test showed were needed: the accessible names of the reorder buttons, text that ran off the side or was cut off at 320 px with large text, and the focus and layout of Remove PDF Metadata. No change to what any tool produces, to any limit, or to where a file is processed. Visible wording is unchanged; the spoken names of the reorder buttons change (decision 2).
**Relates to:** NFR-A11Y-001 to NFR-A11Y-006 (keyboard operation, labels and visible focus, colour not the only signal, error messages, responsive layout, WCAG 2.2 AA), UX specification section 14 and UX-006, UX-007, UX-010, document 08 (testing strategy, accessibility checks), ADR-035 (bad-input matrix, whose wording this test also covers), governance section 14.3.

## Context

Until now accessibility was tested where someone thought of it: an axe scan in a handful of end-to-end tests, a few keyboard assertions, a visible-focus check on the shell. Nothing walked every state of every tool, and nothing looked at text size, narrow screens or what a screen reader is told when a tool changes state. M7E does that and fixes what it finds.

I wrote the test first and ran it against `main` plus the M7D wording, before changing any page. It produced real findings of six kinds, and a handful of faults in the test itself, which I fixed in the test and not in the pages (listed in Evidence). The first CI run then found more than my machine had, because the CI runner's default font is wider than mine; the test now measures in a wide font so that both agree (decision 7).

1. **A name that does not contain the words on the button (WCAG 2.5.3, Label in Name, level A).** The reorder buttons on Organize, Images to PDF and Merge read "Move earlier" and "Move later", but were named "Move page 2 earlier" and "Move file 3 later". A person who says "click Move earlier" to voice-control software does not hit them, because the visible words are not in the name in that order.
2. **Text cut off at 320 px with large text.** The status words in a page thumbnail ("Rendering preview…", "Preview unavailable") are centred in a surface about 124 px wide that hides overflow. With the root text size doubled they did not fit and were clipped.
3. **Long words and fixed minimums ran off the side.** With text doubled at 320 px, long words in the tool guides and the contents links of the Learn guides, the legends of Compress and Images to PDF ("Compression strength", "Page orientation"), the option text in Compress, and the rows of the Rotate result list made the page scroll sideways; Compress's result list used a column minimum of 9 rem that doubled with the text and did the same.
4. **Remove PDF Metadata lost focus.** Choosing a file, getting a result and getting an error each replaced the control that had focus, so focus fell back to the top of the page; every other tool moves focus to the new state's heading. Its before/after table had no layout rule at all and ran off the side of a narrow screen (about 500 px wide at 320 px with text doubled), with nothing to let a keyboard scroll it. Its hidden caption used a Tailwind class, `sr-only`, that nothing else on the site uses; it worked only because Tailwind generates the class when it finds the word in a source file.
5. **Split's page-range field was 320 px tall on phones.** Its flex basis of 20rem is meant as a width in a row; on a narrow screen the group becomes a column and the same value became a height. Not an accessibility rule: it came to light because mobile WebKit's focus check reported the field as covering other text. It is one line tall again.
6. **Everything else held.** The rest of the matrix found nothing: no unnamed controls, no unreachable or trapped controls, no hidden focus, no field error without a description, no target smaller than 24 px, no contrast failures, no missing page title, language or landmark.

## Decisions

**1. One test, four ways of looking, every state.** `apps/web/e2e/a11y-matrix.spec.ts` runs in every browser project. For each page and each state of each tool it applies the same checks and reports every problem found in that state together, so a run lists everything wrong instead of stopping at the first:

| Visitor               | What is checked                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Automated rules       | axe with WCAG 2.0 A and AA, 2.1 A and AA, 2.2 AA and best-practice rules, plus the Label in Name rule that axe keeps behind a flag                                                                                                                                                                                                                                                                         |
| Keyboard only         | Tab through the whole page, forwards, until it comes round again: every control is reached, focus never stays on one element, is never covered by something else, never leaves the page's content invisible, has an outline or ring that contrasts at least 3:1 with what is behind it; fields in error are tied to their message; a control is at least 24 by 24 CSS px, counting its label (WCAG 2.5.8)  |
| Screen reader         | Every control has a name in the browser's own accessibility tree (Playwright's accessibility snapshot, not the DOM); a state a person reached by acting keeps focus somewhere sensible; a state that tells them something new is announced, by focus moving to its heading or an alert, or a live region with text                                                                                         |
| Enlarged text, narrow | At 320 px, at 320 px with the root text size doubled, and with the WCAG text-spacing settings (line height 1.5, letter spacing 0.12 em, word spacing 0.16 em, paragraph gap 2 em): the page does not scroll sideways, no text is cut off by a container that hides overflow, and anything that scrolls inside the page is focusable or holds something focusable, so a keyboard can scroll it (WCAG 2.1.1) |

**2. The reorder buttons begin with their visible words.** The accessible names are now "Move earlier, page 2", "Move later, file 3" and so on: the visible words first, the item after. Screen reader users hear what the button does first and which item second; voice-control users can say what they see. The visible text, the group label ("Reorder …") and every other behaviour are unchanged. Tests that find these buttons by name were updated; no other page text changed.

**3. Thumbnail status text may wrap anywhere.** `.page-thumbnail__surface span` gets `max-width: 100%` and `overflow-wrap: anywhere`. The surface keeps hiding overflow, because it holds a canvas positioned inside it.

**4. Long words may break.** `body { overflow-wrap: break-word }`: a word that cannot fit on a line wraps instead of widening the page. It does not change how words that fit are broken, and it does not change the minimum width of anything, so layout is unchanged for ordinary text. Where `break-word` is not enough, because the element sizes itself to its longest word, the stronger `anywhere` is applied to that element only: every `legend`, the option text in Compress, and the Learn contents links. The Rotate result rows wrap, and the Compress result list uses `minmax(min(100%, 9rem), 1fr)`, the form the other grids on the site already use. Split's range field is `flex: none` in the column layout.

**5. Remove PDF Metadata behaves like the other tools.** Focus moves to the new state's heading when its state changes (the same effect PDF to Text has); the before/after table sits in a labelled, keyboard-focusable region that scrolls inside itself, with a few lines of styling so it has borders and padding like a table should; the caption uses the site's own `visually-hidden` class instead of a Tailwind utility the rest of the site does not use.

**6. A state the test cannot reach is a failure, and the rest still run.** If a scene's set-up throws (a page that never reaches its result), the failure names the scene and says the state could not be reached, and the remaining scenes of that page still run. Otherwise one broken state would hide every later one.

**7. Text is measured in a wide font.** The reflow checks add a style sheet that sets the font to DejaVu Sans (falling back to Verdana, then the default sans-serif), because how much fits on a line depends on the font and a visitor's default is not ours to choose. What fits in a wide font fits in a narrower one. Without this, a developer machine with a narrow default font passes what a CI runner with a wider one fails. Overflow findings name the element, its nearest classed container, the start of its text and where it sits, so a CI annotation is enough to find it.

## Why not more

- **A second automated engine alongside axe.** More rules do not make a different kind of check. The keyboard walk, the accessibility-tree names, the announcement check and the reflow checks are the kinds of problem axe cannot see; they are written as tests of behaviour, so they do not depend on one tool's rule set.
- **`overflow-wrap: anywhere` on the whole page.** It changes the minimum width of every element and can shrink flex and grid items far below readable. `break-word` at the page level plus `anywhere` on the two elements that needed it is the smaller change.
- **Moving focus on every state of every tool automatically from the shell.** The tools differ (some have their own focus rules, such as Split moving focus to the field in error). A shared rule in the shell would have to know all of them. Remove PDF Metadata was the only tool missing it, so it gets the same small effect the others have.
- **Changing the `role="alert"` that wraps the whole error region in the shared tool shell.** A screen reader reads the whole region when it appears, which is more than the message. That is verbose, not wrong, and is the kind of thing real screen-reader testing (M7G) should decide before it is changed.
- **A forced-colours or high-contrast scene.** Not added: the site draws its focus with an outline, which the browser keeps in forced-colours mode, and it uses no background images for meaning. It is a device-level check and goes on the M7G list.

## Evidence

- **The matrix:** 15 tests in each browser project (the ten PDF tools, Images to PDF, Word to PDF, the pages without a tool, the 404 page, and a check that every page has a title, a language, one main landmark and a working skip link) covering 70 states per project: each tool ready, with a file loaded, with its options changed, at its result and at its error; Word to PDF against a scripted server; every static page; the tools search with and without results.
- **Local run, desktop and phone Chromium:** 28 of 30 pass. The two that do not are PDF to JPG's result state, which cannot be reached here (the same three PDF to JPG tests fail on unmodified `main` in this environment). The scene that follows it, the unopenable file, runs and passes, because an unreachable state no longer stops the rest (decision 6).
- **The existing suite after the renames:** 396 pass, 32 fail on the two Chromium projects, 16 in each. They are the 8 that fail on unmodified `main` here (encrypted-PDF classification in Organize, Page tools and Split; the three PDF to JPG tests), the 7 password-protected cases of the M7D matrix (same cause, passing on CI), and the PDF to JPG state above. The Merge, Organize, Images to PDF and Merge privacy tests that press the renamed buttons all pass.
- **Unit tests:** 420 pass. Lint, types, format and the production build pass.
- **The matrix can fail.** I broke nine things one at a time, ran the tests for that page, and restored each: the Move later name changed so it no longer starts with its visible words (caught on Images to PDF as `label-content-name-mismatch` on every reorder button); Remove Metadata's focus effect disabled ("focus was lost to the page body" on its result and error); the thumbnail text rule removed ("text cut off (320 px, text 200%)" on every page tool); Compress's result grid returned to a fixed 9 rem minimum ("the page scrolls sideways"); Split's error description removed ("an invalid field has no error message attached"); the table region's focusability removed ("scrolls but a keyboard cannot reach it"; this one was not caught until I added that check, which is why it exists); the control height token cut to 1 rem ("target too small (WCAG 2.5.8)" on the header links and buttons); the Learn contents link rule removed ("the page scrolls sideways"; caught on this machine because the test now measures in a wide font); and Split's field returned to its 20rem flex basis ("a one-line field is 320 px tall", on phone Chromium). A first pass of this was invalid because a timed-out run left a server on the test port; I repeated it from the start.
- **Five-browser findings the local run could not show:** CI's desktop Chromium and WebKit found four overflows at 320 px with text doubled (Compress options, Rotate result, Images to PDF legends, Learn contents links) that Inter, this machine's default font, hides and DejaVu Sans, which CI draws, shows. They are fixed, the test now measures in a wide font, and a run here with the default font shows the same failures. Mobile WebKit reported Split's range field as covering text, which led to the 320 px tall field (finding 5). Firefox reported focus as stuck on the last footer link on every tool: it keeps focus there after the last control instead of leaving the page, as Chromium does. The walk now treats that as the end of the order when nothing after the control could take focus.
- **Faults in the test itself, fixed in the test:** duplicate element keys in the keyboard walk (it now tracks elements, not names); a walk that began mid-page in states with focus already placed (it goes to the end of the order and starts a second round); radio groups reported unreachable because the arrow keys, not Tab, move within them (a group passes when any member is reached); visually hidden text reported as clipped; PDF to Text reported silent when it had moved focus to its heading; Split's range error checked before the button that raises it was pressed, the wrong heading expected for one output, and focus coverage sampled at the middle of an element that may be taller than the window (it now samples the part that is on screen).
- **Five-browser CI:** all five browser projects pass on the last code commit, 214 tests each; see the milestone report.

## Not covered, and limits

1. **No real screen reader.** The test reads the browser's accessibility tree and checks that the right things change and are announced; it cannot say how VoiceOver, TalkBack, NVDA or JAWS speak them. That is M7G.
2. **Contrast is measured for focus indicators and by axe for text.** axe checks text and control colours that it can compute; it cannot see text on images or in canvases. The pages use none for meaning.
3. **Text size is simulated by doubling the root size and by the text-spacing settings.** Browser zoom, the operating system's text-size settings and a phone's display size are device checks (M7G).
4. **PDF to JPG's result and the encrypted-PDF cases cannot be reached in this environment** (the local Chromium cannot export images in the test and reports encrypted PDFs as unreadable); the same tests fail on `main` here. CI is authoritative for them.
5. **The error region of the shared tool shell is wide** (see "Why not more").
6. **Colour as the only signal, and animation.** The site has no animation and no dark theme; colour is never the only signal in the states the matrix reaches, but there is no automatic check for it beyond axe's link-in-text rule.

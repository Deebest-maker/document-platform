# M4B LibreOffice benchmark harness

This document defines the methodology for benchmarking the LibreOffice headless Word→PDF conversion pipeline. Actual results will be recorded in `M4B-libreoffice-results.json` after a dedicated run against the built container image.

## Objectives

1. Measure end-to-end conversion latency (upload → DOCX preflight → LibreOffice convert → PDF validation → download) for representative workloads.
2. Measure peak memory and disk usage during conversion to inform the container resource limits and the retention-time decision (Governance §9).
3. Verify that the preflight validator rejects all hostile-input classes within a bounded time.
4. Establish a baseline for the page-count sanity bound in `validate_pdf_page_count`.

## Test corpus

| ID  | Description                             | Pages |    Size | Notes                         |
| --- | --------------------------------------- | ----: | ------: | ----------------------------- |
| W1  | Minimal single-paragraph DOCX           |     1 |  ~1 KiB | Baseline latency              |
| W2  | 10-page report with headings and styles |    10 | ~50 KiB | Typical business document     |
| W3  | 50-page document with tables and images |    50 |  ~2 MiB | Mid-range complexity          |
| W4  | 200-page document with embedded images  |   200 | ~10 MiB | Upper boundary stress test    |
| W5  | Maximum allowed input (50 MiB)          |   var |  50 MiB | Size-limit boundary           |
| R1  | Macro-enabled .docm renamed to .docx    |     — | ~10 KiB | Must be rejected by preflight |
| R2  | Encrypted DOCX                          |     — | ~10 KiB | Must be rejected by preflight |
| R3  | ZIP bomb (high compression ratio)       |     — |  ~1 KiB | Must be rejected by preflight |
| R4  | Legacy .doc (OLE compound document)     |     — | ~50 KiB | Must be rejected by preflight |
| R5  | DOCX with path traversal entries        |     — |  ~5 KiB | Must be rejected by preflight |

Corpus files are synthetic (generated by the harness); no real user documents are used.

## Measurements

For each workload W1–W5:

| Metric                      | Method                                                  |
| --------------------------- | ------------------------------------------------------- |
| DOCX preflight (ms)         | `time.perf_counter` around `validate_docx()`            |
| LibreOffice conversion (ms) | `time.perf_counter` around `engine.convert()`           |
| PDF validation (ms)         | `time.perf_counter` around header + qpdf + page count   |
| Total API latency (ms)      | Wall clock from `POST /convert` to response             |
| Output PDF size (bytes)     | `stat()` on the output file                             |
| Output page count           | `qpdf --show-npages`                                    |
| Peak RSS (KiB)              | `/proc/{pid}/status` VmHWM of the soffice child process |
| Workspace disk (bytes)      | `du -sb` on the workspace directory during conversion   |

For each rejection workload R1–R5:

| Metric                 | Method                                        |
| ---------------------- | --------------------------------------------- |
| Rejection latency (ms) | `time.perf_counter` around `validate_docx()`  |
| Error code             | Verify `ProcessorError.code == INVALID_INPUT` |

## Harness script

The harness (`tools/m4b-benchmark.py`, not yet written) will:

1. Build synthetic DOCX files for each workload using `python-docx` or raw `zipfile`.
2. Start the processor in test mode with `LibreOfficeEngine` (not `FakeEngine`).
3. Run each workload 5 times, discard the first (cold), report median and p95 of the remaining 4.
4. Capture per-metric measurements and write them to `M4B-libreoffice-results.json`.
5. Verify all rejection workloads return `INVALID_INPUT` within 100 ms.

## Environment

- Container: the production `Dockerfile` built image.
- Runtime: `docker run` with default resource limits (no `--memory` cap) to measure natural usage.
- Host: record CPU model, RAM, and kernel version in the results file.
- LibreOffice version: `soffice --version` output recorded.
- qpdf version: `qpdf --version` output recorded.

## Decision gates

Per Governance §9, the benchmark results inform:

1. **Retention time** — the Product Owner approves a value based on measured conversion latency + a safety margin.
2. **Concurrency** — if conversion is CPU-bound and long (>5s for W4), concurrency stays at 1. If it's fast (<2s for W3), concurrency > 1 may be considered in a later ADR.
3. **Resource limits** — container memory limit set to 2× peak measured RSS. Disk workspace quota set to 2× peak measured workspace size.
4. **Page-count sanity bound** — set to 2× the maximum observed page count across W1–W5, capped at 1000.

# Requirement-to-test traceability

**Status:** M7I, written 2026-11-04; owner acceptance pending
**Source of the requirements:** document 03 (SRS), 58 functional and 44 non-functional requirements
**Why it exists:** document 08 section 12 and SRS section 16 ask that every P0 functional requirement and every launch-critical non-functional requirement map to at least one automated test or documented manual check. This is that map. It was asked for by the M7G review (finding 4).

## How to read it

Each row is one SRS requirement, the files that cover it, and a status. A row lists files, not single tests: a listed file covers the requirement when at least one test in it does, and the table does not say which one. Tests that name a requirement in their title (`FR-MRG-001/004: ...`) are the closest match.

| Status    | Meaning                                                                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Automated | Tests that run in CI cover the requirement as written. On a pull request the browser tests run in Chromium and mobile Chromium; on `main` they run in all five browsers. |
| Partial   | Tests cover part of it, or some of the tests that cover it do not run in CI. The note says what is missing.                                                              |
| Manual    | Shown by a recorded check or a repository setting, not by a test. The note says what and when.                                                                           |
| Gap       | The product may well do this, but nothing tests it or records it. No evidence is listed.                                                                                 |
| Deferred  | The thing the requirement describes is not built yet. The note starts with the milestone that owns it (M8, M9 or V1.1).                                                  |

**Totals:** Automated 66, Partial 17, Manual 2, Gap 2, Deferred 15 (102 in all)

## What the table shows

1. **Real-engine tests are skipped in CI.** The runner has neither LibreOffice nor qpdf, so 8 processor tests that convert with the real LibreOffice and 4 that check PDFs with qpdf are skipped (CI run of 2026-11-04: 236 passed, 13 skipped, the 13th is a platform quirk in a ZIP test). The real engine was exercised in the M4D benchmark, but nothing re-checks it on each change. FR-W2P-002 and NFR-SEC-002, -003, -004 and NFR-REL-001 are Partial for this reason.
2. **No test drives a page against the real processor.** The Word to PDF browser test answers from a mock; the processor tests call the API directly. The path between them (the page, the proxy, the processor) is first exercised on the M8 staging site.
3. **Two gaps, both small:** no test asserts that no tool asks for an email address (FR-GEN-007), or that a server error log line carries the job identifier (NFR-OBS-003).
4. **Accessibility is automated, not human-verified.** NFR-A11Y-006 is Partial: no real screen reader, no Safari and no iPhone run is recorded (M7 report, decision 5).
5. **Fifteen requirements are deferred, none silently:** four for PDF to Word (V1.1), five for ads (M9), and six for M8 (analytics, monitoring, rollback and the privacy review of both). The M8 six are the launch gate for this table.
6. **Six wrong requirement IDs were found and fixed in this slice** (FR-META-004, -005, -006, FR-P2I-004 and NFR-UX-010, in a test title or an ADR). They named requirements the SRS does not have.

## How it stays true

- `pnpm check:traceability` checks this file against the repository and runs as part of `pnpm test`. It fails when a row is malformed, a cited file does not exist, a requirement is added or dropped, a requirement ID written anywhere in the repository does not exist (`FR-XXX-001/002` and `FR-XXX-001..004` count as several), a test names a requirement but is not listed on its row, or the totals above are wrong.
- `pnpm check:traceability --strict` also fails on every Gap and every requirement deferred to M8. It is the launch-gate form, to be run at the M8 gate.
- To cover a requirement with a new test, put its ID at the start of the test title and add the file to the row. To change a status, change the row and the totals line together.
- What the script cannot check is whether a listed file really covers the requirement. That stays a review question.
